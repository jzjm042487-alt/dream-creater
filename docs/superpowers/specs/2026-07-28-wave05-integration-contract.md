# 《蛊真人：天外盗剧本》Wave 0.5 集成契约

日期：2026-07-28

状态：活动中的最高层集成契约

## 1. 目标与基线

Wave 0.5 不扩写第二套玩法，也不把全部剧本一次性改造成运行时数据。它负责把 Wave 0 已确认的
剧情、系统、原型、美术和原著资料放入同一条可验证基线，使五个执行角色在 Wave 1 中不会各自引用
不同的“最高权威”。

当前基线保留：

- `docs/game-design/qing-mao-mvp-script/` 的 10 文件状态化生产包与 144 条记录。
- 精简 MVP 的方向旅行、低阶蛊、格子战斗、分类关系图和一次判定偷盗。
- 当前 16 视图可交互 UI 原型、玩家八帧行走图和已有场景与角色资产。
- `contracts/`、`systems/` 和原著提取结果形成的机器可读基础。

## 2. 权威层级

1. 本文决定跨角色边界、冲突裁决和 Wave 1 入口。
2. `2026-07-27-qing-mao-simplified-mvp-design.md` 决定系统范围、公式和明确删除项。
3. `2026-07-27-qing-mao-mvp-stateful-dialogue-script-design.md` 与
   `docs/game-design/qing-mao-mvp-script/` 决定剧情事实、触发条件、台词和结果。
4. `contracts/` 与 `systems/` 决定已经落地的运行时数据形状和稳定 ID。
5. `src/ui-prototype/` 决定当前可试玩原型的实际交互；视觉规格提供目标表现，不覆盖已验证行为。
6. `systems/canon/curated/` 是机器可读原著事实源；设定摘录和 GDD 只提供说明。

冲突裁决遵循“状态化叙事、精简系统”：剧情可以记录任务、物品、知识、世界和普通 NPC 状态，
但不能借剧情条件重新引入已删除的全局压力数值或专属方源系统。机器契约尚未覆盖的编剧字段属于
待编译输入，不得因为旧 Schema 较小而删除已批准剧情。

## 3. 不可回退的产品决策

- 玩家是唯一主角；方源是可竞争、可交易、可冲突、可死亡的普通 NPC。
- 不创建数值好感、信任、怀疑、功绩、全局方源警觉、原轨同步率或世界纠偏值。
- 人物关系使用有方向的分类关系边，不用数值决定任务资格。
- 主线始终有至少一个合法继续选项；休息、绕路和错过可选机缘不会卡死主线。
- 支线和机缘可以被拒绝、过期、失败或被其他角色取得，并留下可理解的世界反馈。
- 条件不满足的选项可以显示为不可用，但必须显示具体原因，且不能成为主线唯一出口。
- 偷盗是主技能，地图内一次选择、一次判定；允许即时资源代价、战斗和关系状态反应。
- 偷盗成功后物品进入普通行囊；MVP 不建立赃物溯源、长期追查、热度、嫁祸或洗白系统。
- 野图隐藏路径由玩家方向选择发现，第 20 步只保底普通目的地，不暴露隐藏地点。

## 4. 跨角色接口

### 4.1 编剧记录到运行时

- `D_`、`I_`、`B_` 开头的 ID 是全局唯一的编剧记录 ID，不等同于现有 `dlg_*` 示例节点。
- `requires`、`excludes`、`available_from`、`expires_after` 和 `on_expire` 是编剧输入字段。
- Wave 1 必须把条件转换为结构化谓词，把写入转换为结构化原子动作；禁止直接执行或 `eval`
  Markdown 中的表达式。
- 允许的谓词域为日期、地点、任务、物品、知识、世界事实、普通 NPC 事实和明确能力条件。
- 选项结果必须先完整验证，再一次写入；唯一物品转移必须先确认原持有人和目标持有人。
- 当前 `contracts/dialogue.schema.json` 继续服务 Demo V2 示例，不能反向裁剪 144 条生产记录。

### 4.2 ID 与别名

- 运行时稳定 ID 使用 `contracts/demo-v2-ids.json` 中的注册值。
- 剧本里的 `GU_*`、`ITEM_*` 是编剧 ID；转换时必须经过显式别名表，禁止仅靠大小写或字符串
  替换猜测对应关系。
- 未注册的人物、地点、物品和记录先进入 Wave 1 注册清单，再生成 JSON；不得静默丢弃引用。

### 4.3 UI

- `UI00` 等编号只标识当前原型视图，不写入任务、剧情或长期存档。
- 对话动作只引用 `panel_character` 等语义面板 ID。
- `src/ui-prototype/panelRegistry.js` 的 `RUNTIME_PANEL_TO_PROTOTYPE` 是语义面板到原型视图的
  唯一映射；没有映射的视图属于开局、地图、对话、战斗或结算流程，不伪装成 `openPanel` 目标。

### 4.4 偷盗与野图

- 酒虫 Demo 的盗藏隐藏点要求到达 `node_qm_theft_cache` 且
  `theftMastery >= 20`。
- 数据使用 `nodeAndAttributeThreshold`、`attributeId` 和 `minimumValue` 表达该条件，不生成
  `flags.theftRankAtLeast1` 之类的派生布尔值。
- 判定和随机游标必须可存档、可复现；读档不能重掷结果。

### 4.5 美术

- 美术交付使用稳定角色或场景 ID、用途、尺寸、帧布局和情绪标签，不以中文文件名作为接口。
- 对话大图、地图小图、情绪变体和动作图分开登记；缺失项使用显式待办测试，不放入伪完成占位图。
- Wave 1 首批只覆盖 Q01 酒虫路线和主线必见人物，之后再扩到其余支线。

## 5. Wave 1 入口

Wave 1 采用 Q01 酒虫纵向切片，而不是五条支线并行数据化：

1. 剧情角色把 Q01 与其主线前置编译为结构化谓词、动作和节点，并提供成功、失去、拒绝、错过四类走查。
2. 系统角色补齐谓词、动作、记录 ID 与编剧 ID 别名契约，保持一次判定偷盗和主线不断档。
3. 美术角色按 Q01 实际出场清单交付地图小图、对话大图和需要的情绪变体。
4. 代码角色只接入已经注册并通过验证的 Q01 数据，不在组件中硬编码剧情分支。
5. QA 角色覆盖纯主线、不接触方源、酒虫成功、酒虫被他人取得、过期和读档不重掷。

允许进入 Wave 1 的门禁：

- `node scripts/validate-contracts.mjs`
- `node scripts/validate-content.mjs`
- `node scripts/validate-canon.mjs`
- `npm test`
- `npm run build`
- `npm run test:e2e`

NPC 专用地图动作图仍可作为显式跳过的待办，但不得把跳过测试描述成已完成资产。
