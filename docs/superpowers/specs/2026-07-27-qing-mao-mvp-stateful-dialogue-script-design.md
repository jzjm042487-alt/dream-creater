# 《蛊真人：天外盗剧本》青茅山 MVP 条件对话剧本重构规格

日期：2026-07-27

状态：Wave 0.5 叙事权威，生产剧本已完成

跨角色权威层级与运行时转换边界见
`2026-07-28-wave05-integration-contract.md`。本规格决定剧情事实、条件和结果；
精简 MVP 总契约决定系统排除项。

本规格取代 `2026-07-26-qing-mao-mvp-complete-script-design.md` 中的视觉小说式演出结构，
并指导 `docs/game-design/qing-mao-mvp-script/` 的完整重写。旧稿中的可用剧情事实、角色动机、
任务奖励和世界时间继续作为素材；镜头、动作、旁白、每日强制场景和围绕方源组织的主线全部废弃。

## 1. 目标

青茅山 MVP 使用常规 RPG 的状态驱动对话树：

1. 玩家前往地点。
2. 玩家找到在场 NPC 或可交互物。
3. 系统根据当前状态选出该对象可触发的对话节点。
4. NPC 说出当前台词，玩家选择一句完整回答。
5. NPC 作出对应回应，系统修改任务、关系、物品或时间状态。
6. 对话结束。
7. 后置对话在玩家下次于正确地点找到正确角色时出现。

正式剧本必须提供一条玩家主线、五条完整支线、关键 NPC 的状态对白和新手村限定奖励闭环。
玩家角色固定为男性古月旁支，可选择姓名；属性、资质、天赋、缺陷与命格由确认角色前的随机 Roll
产生。MVP 使用固定立绘和 Q 版角色，不选择性别、脸型、发型、肤色、身高或立绘模板。

## 2. 明确取消的设计

以下内容不得进入新剧本：

- 视觉小说式连续场景。
- 镜头、视角、立绘调度、动作演出、音效指令和不可交互旁白。
- 每日开始时自动播放的强制主线。
- 由一个对话节点自动传送到新地点或自动完成调查、战斗、偷盗和移动。
- 为每一句普通回答建立独立永久旗标。
- 独立的方源敌意、警觉、每日计划和特殊反制系统。
- 要求玩家持续观察、追踪、竞争或改变方源的主线目标。
- 任何必须与方源交谈才能继续的主线阶段。
- 以“原作同步率”评价或惩罚玩家偏离原作。
- 方源对原作机缘、任务和世界资源的默认优先权。

## 3. 玩家与世界定位

玩家是本游戏唯一主角。原作文本提供世界规则、人物背景、已知事件和可利用的情报，不规定玩家必须
围绕原作主角行动。

主线关注玩家自己的经历：

```text
生成古月旁支身份
→ 完成开窍并在学堂立足
→ 建立自己的修炼构筑
→ 获取财富、身份或外部渠道
→ 为狼潮准备生存资源
→ 应对青茅山覆灭
→ 携带自己的任务结果永久离山
```

原作事件仍会按世界日历推进。玩家不介入时，NPC 可以取得资源、死亡、离场或完成自己的目标；
这属于普通世界结算，不是为方源保留剧情。

“新世界游戏生成器”只承担玩家 UI 工具：

- 区分原作记录、当前已验证事实和未验证推测。
- 提供玩家已查询到的原作情报。
- 报告世界状态变化与任务截止。
- 不在世界内参与 NPC 对话。
- 不评价玩家是否忠于原作，也不评价选择善恶。

## 4. 常规交互架构

### 4.1 世界出场系统

世界系统负责：

- 当前日期与时段。
- 当前地点。
- NPC 是否在场。
- NPC 因任务结果而离开、死亡或更换地点。
- 可交互物是否存在、已取走或已损坏。

角色出场规则不写进台词正文。对话节点只引用角色、地点和状态。

### 4.2 对话解析器

玩家与 NPC 交互时，解析器依次执行：

```text
查找该 NPC 的全部节点
→ 匹配当前地点
→ 匹配日期和时段
→ 检查任务阶段与世界状态
→ 检查所需物品、属性、天赋和关系
→ 排除已消费、已过期或被互斥结果关闭的节点
→ 选择优先级最高的有效节点
```

普通 NPC 直接进入当前最合适的节点，不先展示话题菜单。商人、导师等长期功能型 NPC 可以先显示
“交谈、交易、请教”等功能入口；任务对话仍由相同解析规则选择。

优先级使用固定数值，不允许编剧自行增加新档：

| 优先级 | 节点用途 |
| ---: | --- |
| 100 | 当前时段结束后就会失效的最后提醒 |
| 80 | 当前主线的新节点 |
| 70 | 任务成功、失败、拒绝或错过后的首次回应 |
| 60 | 当前支线的新节点 |
| 30 | 已完成任务的重复状态回应 |
| 10 | 日常重复台词 |

解析器在当前交互拥有者的候选记录中选择最高有效优先级。该优先级只有一个记录时直接进入；存在
两个或更多记录时，这些记录必须各自声明简短 `topic`，系统只显示这些同优先级话题供玩家选择。
相同优先级的显示顺序按 ID 升序固定。缺少 `topic` 的并列记录属于内容错误。NPC 与物件遵守同一
并列规则。

### 4.3 对话运行器

标准节点运行过程：

```text
NPC 开场
→ 玩家选择完整回答
→ 必要时执行一次对话判定
→ NPC 显示对应回应
→ 原子写入全部状态
→ 标记节点已访问或已消费
→ END
```

每个节点只能提供一轮玩家选择，选择后显示对应 NPC 回应并 `END`。不使用 `inline_next`，也不在
同一次交谈中进入第二组选项。需要继续追问时，写成新的条件节点，由玩家结束交谈后再次互动。

查看 NPC 台词与选项不消耗时间。只有当选项本身完成一次交谈行为，例如交易、说服、欺骗、接受
委托或提交材料时，才显式消耗元石或推进时段。MVP 不使用行动点。

## 5. 对话节点格式

### 5.1 必需字段

三类记录使用同一份固定头部，不允许省略字段：

```text
类型：dialogue / interaction / bark
ID：全局唯一 ID，与二级标题一致
所属：MAIN / Q01 / Q02 / Q03 / Q04 / Q05 / GENERAL
拥有者：npc.<id> / object.<id>
地点：规范地点 ID
available_from：包含边界的日期时段 ID
expires_after：包含边界的日期时段 ID
priority：100 / 80 / 70 / 60 / 30 / 10
topic：并列时显示的短话题；不适用写 none
requires：全部必需条件；没有写 none
excludes：任一成立即排除的条件；没有写 none
once：true / false
on_expire：到期时的状态写入；没有写 none
```

字段值 `none` 是正式值，不得用空白、省略号或“无”代替。`once=true` 时系统以 `visited(ID)` 自动
排除已经完成的记录，不需要在 `excludes` 中重复书写。

`dialogue` 正文必须包含角色、NPC 开场台词，以及每项玩家选择各自的判定、NPC 回应、写入和
`END`。`interaction` 正文必须包含物件提示，以及每项操作各自的判定、事实结果、写入和 `END`。
`bark` 正文必须包含角色可知的一段状态台词、写入和 `END`。

对话节点 ID 全局唯一，格式为：

```text
D_<任务ID或MAIN>_<角色ID>_<两位序号>
```

示例：`D_Q01_TAVERN_KEEPER_02`。

### 5.2 标准书写模板

```text
## D_Q01_TAVERN_KEEPER_02

类型：dialogue
ID：D_Q01_TAVERN_KEEPER_02
所属：Q01
拥有者：npc.tavern_keeper
地点：tavern
available_from：D05_afternoon
expires_after：D08_evening
priority：60
topic：none
requires：
- quest.q01.stage == "smell_found"
excludes：none
once：false
on_expire：none

[酒肆掌柜]
“又是你。后院那两坛酒我挪开了，你若还惦记，就先告诉我它们有什么问题。”

[选择 A]
[玩家]
“酒没有坏。是里面的东西在找酒气。”

[判定]
none

[酒肆掌柜]
“听着不像酒客的话。你想查可以，出了事别说是我放你进去的。”

[写入]
quest.q01.stage = "back_room_open"

[结束]
END

[选择 B]
[玩家]
“没什么，只是确认你没有把坏酒卖给我。”

[判定]
none

[酒肆掌柜]
“真喝坏了，拿酒坛来找我。没凭没据，就别惦记我的后院。”

[写入]
none

[结束]
END
```

节点中不允许出现：

- `[镜头]`
- `[动作]`
- `[旁白]`
- `[音效]`
- “进入某路线”而没有对应人物台词
- “玩家进行了合理解释”而没有写出玩家实际说法

### 5.3 选择与判定

玩家选项必须是角色真正说出口的完整句子。纯世界行动由地图、调查、战斗、交易或偷盗系统提供，
不伪装成对白选项。

普通回答不做判定。只有说服、欺骗、威胁、套话等对话行为可以声明判定：

```text
判定：魅力 + 对应天赋修正，对抗难度 60
成功回应：……
失败回应：……
```

判定结果写入一次并持久化。再次交谈只读取结果，不重复投掷。

对话选择允许直接产生的效果只有：

- 接受、拒绝或汇报任务。
- 修改任务阶段、路线或关系。
- 完成说服、欺骗、威胁或套话判定。
- 交付双方当场明确同意交易的物品、元石或证据。
- 解锁一个地点、NPC 话题或可交互物。
- 消耗该次交谈明确标注的元石或推进时段。

对话选择不得直接完成移动、搜索房间、检查物件、战斗、跟踪、偷盗、炼化或其他外部玩法。
例如“我替你检查后院”只能取得许可并解锁后院酒坛，不能同时写入“已检查酒坛”。

### 5.4 物件交互记录

任务需要检查档案、酒坛、痕迹或其他物件时，使用独立的 `interaction` 记录，不伪装成 NPC 对话：

```text
## I_Q01_BACK_ROOM_JAR_01

类型：interaction
ID：I_Q01_BACK_ROOM_JAR_01
所属：Q01
拥有者：object.back_room_jar
地点：tavern_back_room
available_from：D05_afternoon
expires_after：D08_evening
priority：60
topic：none
requires：
- quest.q01.stage == "back_room_open"
excludes：none
once：false
on_expire：
- quest.q01.stage = "missed_tavern_window"

[提示]
检查后院异香酒坛

[操作 A]
辨认酒香

[判定]
none

[事实结果]
“封泥没有漏，异香来自酒坛内部，并且正缓慢向墙缝移动。”

[写入]
quest.q01.stage = "trail_found"
player.knowledge += "wine_scent_moves"

[结束]
END

[操作 B]
查看封泥

[判定]
none

[事实结果]
“封泥完整，没有重新开启过；坛口残留的酒气与普通青竹酒不同。”

[写入]
player.knowledge += "jar_seal_intact"

[结束]
END

[操作 C]
离开

[判定]
none

[事实结果]
“未进行检查。”

[写入]
none

[结束]
END
```

物件记录 ID 使用 `I_<任务ID或MAIN>_<物件ID>_<两位序号>`。其中的可选操作是地图交互命令，
不是玩家说出口的台词；结果只陈述玩家确认到的事实，不写镜头、动作演出或全知旁白。

### 5.5 日常与状态回应

没有新任务节点时使用 `bark`：

```text
## B_TAVERN_KEEPER_Q01_COMPLETE_01

类型：bark
ID：B_TAVERN_KEEPER_Q01_COMPLETE_01
所属：Q01
拥有者：npc.tavern_keeper
地点：tavern
available_from：D05_afternoon
expires_after：D30_evening
priority：30
topic：none
requires：
- quest.q01.result == "player_acquired"
excludes：none
once：false
on_expire：none

[酒肆掌柜]
“后院清净了。你拿走了什么我不问，别再把同样的麻烦带回来。”

[写入]
none

[结束]
END
```

`bark` ID 使用 `B_<角色ID>_<状态ID>_<两位序号>`。它由所写角色拥有，只能包含该角色能知道的
事实。纯日常台词使用状态 ID `AMBIENT`，优先级为 10。

### 5.6 不属于剧情记录的系统流程

以下内容是系统界面或世界结算，不使用 `dialogue`、`interaction` 或 `bark` 伪装：

- 新游戏中的姓名选择与角色 Roll 确认。
- 日期和时段推进。
- 到期状态结算。
- 第 30 日离山路线确认与限定奖励缺失清单。
- 最后时段仍未选择路线时的紧急流亡兜底。

这些流程只在 `00-quest-overview.md` 与 `08-schedules-states-rewards.md` 中登记输入、状态写入和后续
可用节点，不编写镜头、动作或连续剧情。

## 6. 简化状态模型

### 6.1 默认状态

对话主要读取：

```text
world.day
world.period
world.flags
quest.<id>.stage
quest.<id>.route
quest.<id>.result
player.attributes
player.traits
player.inventory
player.knowledge
npc.<id>.relationship_state
item.unique.<item_id>.owner
visited(<node_id>)
choice(<node_id>)
```

常规任务推进优先使用 `quest.<id>.stage`。节点访问由系统自动记录。只有会长期改变后续内容的关键
决定才写入 `route`、`result` 或 `choice`；普通礼貌回答不建立永久变量。

### 6.2 方源状态

方源不声明专属状态结构，直接使用所有普通 NPC 共用的事实字段：

```text
npc.<id>.met_player
npc.<id>.relationship_state
npc.<id>.known_facts
npc.<id>.transactions
npc.<id>.direct_conflicts
```

方源将 `<id>` 取值为 `fang_yuan`，不额外增加字段。没有独立警觉条、敌意条、原作主角 AI 或
无条件反制。只有方源亲眼见过、从可信来源得知或与玩家直接交易过的事实，才能改变他的后续台词。

所有方源节点均可跳过。任何任务如果允许从方源取得信息，也必须提供其他 NPC、现场痕迹、档案或
可交互物入口。

### 6.3 原子结算

玩家确认选项后，系统必须在一次结算中完成：

- 判定结果。
- NPC 回应选择。
- 任务阶段变化。
- 关系状态、物品、元石和时间变化。
- 节点访问记录。

其中任何一步无效时不得写入部分状态。唯一物品转移必须先移除原持有人，再写入新持有人。

## 7. 剧情结构

日期继续作为世界日历和截止条件，不再作为连续剧本章节。主线与五条支线统一采用：

```text
接触节点
→ 调查节点
→ 回报或回应节点
→ 关键决策节点
→ 结算节点
```

调查物件使用 `interaction` 记录；战斗、移动、商店购买和偷盗由对应玩法完成。对话负责告知目标、
回应已经发生的结果、提供人物选择和结算奖励。任何对话节点都不能代替这些外部玩法写入完成结果。

### 7.1 主线《剧本之外》

主线只服务玩家成长：

1. 创建角色并确认姓名、属性、资质、天赋、缺陷与命格。
2. 在旧屋、族务堂和学堂完成旁支身份落地。
3. 参加开窍并取得基础蛊与修炼权限。
4. 通过学堂任务建立第一套可玩的修炼构筑。
5. 接触商队、家族或灰色渠道，准备离山身份。
6. 加入或避开外勤任务，为狼潮准备物资和路线。
7. 在青茅山覆灭时选择已解锁路线并永久离山。

主线可以使用学堂家老、族务执事、守卫、商队账房、青书副手和任务物件作为信息入口。
主线不得检查玩家是否见过方源。

### 7.2 Q01《月下酒虫》

```text
酒肆掌柜提供异香线索
→ 玩家调查酒坛、后院或购买记录
→ 玩家在正确地点寻找酒虫
→ 根据到达时间处理当前持有人或竞争者
→ 炼化、交易、夺取、放弃或错过
→ 掌柜与相关 NPC 提供结果对白
```

方源可以成为某一状态下的竞争者或持有人，但不是任务必见角色。

### 7.3 Q02《花酒遗藏》

```text
从酒虫、影壁痕迹、族史档案或现场调查获得入口
→ 分层探索遗藏
→ 处理家族、同伴或其他探索者的归属要求
→ 选择不同房间和资源
→ 在入口坍塌前完成最后一次取物
→ 结算蛊虫、密道图和知情者状态
```

Q02 的信息和进入方式不得只由方源提供。

### 7.4 Q03《贾金生遗案》

```text
接触贾金生或商队账房
→ 选择合法交易、私货、观察或拒绝
→ 案件发生后调查现场、证人和货物流向
→ 向贾富或铁家提交、隐瞒、伪造或出售证据
→ 锁定合法商路或灰色商路奖励
→ 在离山前接受最终案件后果
```

案件事实可以受 NPC 行动改变，但玩家不是方源案件的旁观者；玩家自己的交易、证据和选择是该线
叙事中心。

### 7.5 Q04《九叶生机草》

```text
通过遗产账目、药堂或舅父舅母得知九叶生机草
→ 调查所有权与保管地点
→ 选择合法主张、交易、偷取、委托保管或上缴
→ 处理药堂、江牙和家族的后续要求
→ 在截止前确定最终持有人
→ 结算持续经济或一次性保护奖励
```

### 7.6 Q05《青书的死局》

```text
由青书、青书副手或外勤任务开启
→ 收集至少两类危险证据
→ 完成至少两项撤退准备
→ 向青书或队伍提交可验证信息
→ 在任务地点执行救援、顶替、撤退或放弃
→ 结算青书命运、队伍伤亡与遗民关系
```

“知道原作结局”只能提供调查方向，不能代替证据、准备和人物动机。

## 8. 角色与台词标准

### 8.1 台词完整度

每个关键 `dialogue` 必须具备：

- NPC 开场 1–3 句。
- 玩家回答 2–4 项。
- 每项回答后的 NPC 回应 1–3 句。
- 判定存在时的成功与失败回应。
- 任务结束、失败和错过后的状态对白。

关键 `interaction` 按 5.4 的逐操作格式完整书写，不需要伪造 NPC 开场或玩家口头回答。
不得只写策划摘要。所有世界内对话选择必须让玩家知道自己实际说了什么。

### 8.2 玩家台词

现实玩家清楚自己正在玩根据小说生成的游戏。世界内角色不会直接对 NPC 说“你是小说人物”、
“原作中你会死”或“我读取了剧本”。玩家可以说出世界内合理的推断、警告、报价和谎言。

### 8.3 核心声音

| 角色 | 台词规则 |
| --- | --- |
| 方源 | 普通可选 NPC；短句，核算利益，只追问自己有理由知道的事实 |
| 方正 | 在认可、家族责任和兄长关系之间摇摆 |
| 学堂家老 | 以家族价值、纪律和资源回报评价弟子 |
| 青书 | 追问谁承担任务、谁负责撤退，不接受无证据预言 |
| 贾金生 | 用夸张报价和吹嘘遮掩对贾富的恐惧 |
| 贾富 | 只谈账目、损失、来源和可验证事实 |
| 白凝冰 | 直接讨论危险与生死，兴趣不等于好感 |
| 铁若男 | 核对时间线、来源和矛盾，不猜测内心 |
| 酒肆掌柜 | 关心生意、麻烦和酒肆责任，不主动卷入争斗 |
| 禾娘 | 精于小账，不白吃亏，也不替玩家承担大风险 |

关系变化只选用“陌生、正常、合作、冲突”等少量有意义的台词状态，不为每一点数值创建新版本。

### 8.4 必写角色与覆盖范围

“关键记录”指满足任一条件的 `dialogue` 或 `interaction`：

- 修改主线或支线阶段、路线、结果。
- 转移唯一物品或限定奖励。
- 开启、关闭地点或离山路线。
- 执行对话判定。
- 确定主要 NPC 生死、离场或长期关系状态。

关键 `dialogue` 使用完整台词标准，关键 `interaction` 使用逐操作事实结果标准。主要 NPC 明确为：

```text
族务执事
学堂家老
方正
酒肆掌柜
禾娘
古月青书
贾金生
贾富
古月药姬
江牙
舅父
舅母
白凝冰
铁若男
```

方源是可选支持 NPC，不属于必写主线角色；只有具体可选任务分支使用他时才编写对应节点。

每条任务至少覆盖下表中的节点功能：

| 内容 | 必写参与者 | 必写节点功能 |
| --- | --- | --- |
| 主线 | 族务执事、学堂家老、至少一名离山路线联系人 | 身份落地、开窍结果、学堂立足、离山准备、主动离山、紧急流亡 |
| Q01 | 酒肆掌柜、结算时的酒虫持有人 | 线索、许可或交易、归属结算、玩家成功、被他人取得、错过 |
| Q02 | 入口线索提供者、遗藏归属主张者 | 入口、每层结果、资源选择、入口关闭、成功深度、错过 |
| Q03 | 贾金生、贾富、铁若男或其明确替代者 | 初次交易、路线选择、案件回应、证据处置、路线奖励、最终后果 |
| Q04 | 舅父、舅母、古月药姬、江牙 | 所有权线索、主张或交易、最终持有人、自留、上缴、失去或错过 |
| Q05 | 青书、青书副手、白凝冰或危险证据提供者 | 招募、两类证据、两项准备、最终决定、生还、死亡、拒绝或错过 |

对每名实际参与任务结算的主要 NPC，至少提供一条结算后 `bark`。NPC 已死亡、永久离场或从未知道
任务事实时不强行补写状态对白，由其他知情角色或任务日志承担结果说明。

## 9. 奖励与新手村限定物

### 9.1 五条支线核心奖励

| 来源 | 核心奖励 | 中期价值 | 最后窗口 |
| --- | --- | --- | --- |
| Q01 | 酒虫 | 提高一转真元质量，开启后续四味酒虫路线 | 第 10 日 |
| Q02 | 白豕蛊、玉皮蛊、隐石蛊、花酒密道图 | 力量、防御、藏匿、合炼与离山路线 | 第 25 日 |
| Q03 | 贾家通行商令，或袖囊蛊与黑市名册 | 合法商路或灰色商路；两类奖励互斥 | 第 27 日 |
| Q04 | 九叶生机草，或药堂元石报酬与保命药物 | 持续治疗经济，或低维护一次性保护 | 第 24 日 |
| Q05 | 青书信物、青藤护符 | 遗民接应与一次致命物理伤害保护 | 第 25 日 |

Q02 的奖励按探索深度发放：

- 正常完成稳定取得一只核心蛊。
- 准备充分可以取得两只。
- 深度探索并承担高成本，才可能取得三只与完整密道图。

### 9.2 隐藏限定物

| 物品 | 来源 | 作用 |
| --- | --- | --- |
| 癞土蛤蟆 | 商队紫金石 | 出售取得启动资金，或保留为后续炼道素材 |
| 赤铁舍利蛊 | 最后一次商队补给 | 推动一转修为；每存档一只 |
| 家族历史记录 | 花酒影壁特殊处置 | 改变家族与调查中的谈判条件 |
| 青书支援 | 青书救援准备 | 狼潮中自动完成一个战斗目标，使用后消失 |

限定物必须具有立即用途、中期用途和明确维持成本或路线代价。它们不能替代任务证据、人物动机和
必要准备。

### 9.3 永久离山

第 30 日确认离山时：

- 已发现但未取得的限定物显示名称和最后取得地点。
- 未发现的隐藏物只显示“仍有未确认的限定资源”。
- 玩家确认后写入 `world.village_closed = true`。
- 青茅山地点、商店、任务和原始奖励来源永久关闭。
- 后续可以取得升级材料，不能重新生成错过的基础蛊、信物和通行权。

## 10. 失败、错过与替代入口

### 10.1 主线

主线不得因漏掉一句台词而永久卡住。必要 NPC 缺席时使用：

- 同职能 NPC。
- 学堂或家族档案。
- 现场痕迹。
- 可交互任务物件。
- 更高成本的补救节点。

替代入口只保证主线信息与离山可达，不保证原 NPC 的关系奖励和专属信物。

### 10.2 支线

支线允许：

- 拒绝任务。
- 错过截止。
- 关键 NPC 死亡或离场。
- 奖励被其他 NPC 取得。
- 因互斥选择永久关闭一条路线。

支线失败后，玩家再次找到相关 NPC 时必须得到具体失败或事后台词，任务日志记录失败原因与最后窗口。
五条支线全部失败时，主线仍提供紧急流亡路线。

### 10.3 截止时间

所有时间窗口使用包含边界的两个字段：

```text
available_from：最早可用日期与时段，包含该时段
expires_after：最后可用日期与时段，包含该时段
```

例如 `available_from=D05_afternoon`、`expires_after=D08_evening` 表示节点从第 5 日午后开始可用，
并在第 8 日傍晚结束时失效。只有在玩家结束当前交互并主动推进时段后，截止结算器才运行。
策划表只写日期而省略时段时，默认 `available_from` 为当日早晨，`expires_after` 为当日傍晚结束。
截止结算器只对到期瞬间仍满足 `requires`、不满足 `excludes` 且尚未因 `once=true` 被消费的记录执行
`on_expire`。
同一个任务阶段只能指定一条记录拥有非 `none` 的 `on_expire`；同阶段其他记录必须写
`on_expire：none`，避免重复结算。

截止结算只修改状态，不播放剧情：

```text
quest.<id>.stage = "missed"
quest.<id>.result = <具体错过原因>
关闭尚未取得的对应奖励
开放优先级 70 的一次性错过回应
```

第 30 日规则固定为：

1. 第 30 日开始时写入 `world.departure_open = true`，开放玩家已经满足条件的离山交互点。
2. 玩家在任一离山交互点选择路线后，系统显示不可逆确认和已知限定奖励缺失清单。
3. 玩家确认后立即写入 `world.village_closed = true`。
4. 如果玩家推进完第 30 日最后一个时段仍未确认路线，系统直接结算紧急流亡，不播放强制对话，
   随后写入 `world.village_closed = true`。
5. `world.village_closed = true` 后，任何青茅山 NPC、物件、商店和任务节点都不再可用。

### 10.4 无可用节点

NPC 没有任务节点时：

- 有合适日常台词则播放一条 `fallback`。
- 没有可说内容则显示简短的当前状态回应并结束。
- 不弹出错误，不自动播放其他角色的节点。

## 11. 成品文件结构

### 11.1 本轮工作边界

本规格当前只指导生产剧本 Markdown 的重写。当前实施计划包括：

- 重写下列剧本文件。
- 建立节点、角色出场、状态、奖励和流程索引。
- 以文档走查验证所有代表性分支。
- 使用仓库文本检查发现禁止标签、重复 ID、缺失回应和未结束节点。

当前实施计划不包括：

- 修改对话解析器、地图、UI、存档或任务运行时代码。
- 把 Markdown 编译成 JSON、Yarn、Ink 或其他运行时格式。

运行时接入必须在剧本文档通过验收后另行设计和计划。本规格中的解析顺序、原子结算和运行时条件

## 12. 数据错误处理

实现前的内容校验必须拒绝：

- 重复节点 ID。
- 缺少 5.1 任一固定头部字段，或用空白代替正式值 `none`。
- 使用非规范日期时段 ID 或固定表之外的优先级。
- 引用不存在的 NPC、地点、物品或任务阶段。
- 未解析的模板变量。
- 没有 NPC 回应的玩家选项。
- 没有 `END` 的分支。
- 同一节点出现第二轮玩家选择。
- 主线只能由方源提供的必需信息。
- 唯一物品同时拥有多个持有人。
- 截止后仍能领取已关闭奖励。
- 并列最高优先级节点缺少 `topic`。
- `dialogue`、`interaction` 或 `bark` 使用了错误的必需字段。

未来运行时必须在玩家确认选择前重新检查条件。条件失效时不结算，关闭旧选项并重新解析当前 NPC
节点。本轮文档重写只需把这一行为写成节点契约，不实现运行时代码。

## 13. 验证方案

### 13.1 静态校验

- 所有节点 ID 唯一。
- 所有任务阶段、状态键和跳转目标存在。
- 每个选项都有玩家台词、NPC 回应、状态结果和结束方式。
- 每个物件交互都有提示、可选操作、事实结果、状态结果和结束方式。
- 每条 `bark` 都有明确所有者、可知事实、状态条件和结束方式。
- 每条任务都有成功、失败、拒绝和错过终点。
- 所有新手村限定物都有唯一来源、最后窗口和永久错过结果。

### 13.2 流程校验

通过文档中的状态追踪表逐步走查以下场景。本轮验收的是节点图与状态结果自洽，不声称这些场景
已经接入可执行游戏存档。

| 走查场景 | 必须成立 |
| --- | --- |
| 不接触方源 | 从创建角色到永久离山全程可完成 |
| 纯主线 | 五条支线全部忽略，主线仍可达紧急流亡 |
| Q01 成功/失败 | 酒虫所有权与后续台词正确 |
| Q02 一件/两件/全探索 | 奖励深度和入口截止正确 |
| Q03 合法/黑市 | 两类路线奖励互斥，案件后果不同 |
| Q04 自留/上缴/失去 | 最终持有人、收益与状态对白正确 |
| Q05 救援/顶替/死亡 | 青书命运、信物、护符与队伍后果正确 |
| 全限定收集 | 唯一物品不重复，离山携带正确 |
| 全部错过 | 离山前提示正确，确认后永久关闭 |
| 不同 Roll 角色 | 属性、天赋和背景只改变合法选项与判定，不阻断主线 |

静态校验可以由仓库文本命令或人工检查表完成，不要求本轮新增通用剧情解析器或测试框架。

### 13.3 台词验收

- 正文不存在镜头、动作和旁白标记。
- 玩家选项都是实际说出口的句子。
- NPC 不知道自己无法获知的玩家行为。
- 任务完成、失败和错过后，主要 NPC 均有状态回应。
- 方源所有对话都可跳过。
- 台词符合各角色稳定利益逻辑，不靠作者说明人物动机。

## 14. 完成定义

剧本重构完成必须同时满足：

1. 一条玩家主线与五条支线全部采用条件 `dialogue`、`interaction` 与 `bark` 记录。
2. 所有关键对话节点具有完整 NPC 台词、玩家选项和逐项回应。
3. 除第 30 日最后时段的紧急流亡兜底外，所有推进都来自玩家在正确地点主动找到角色或物件。
4. 日期只改变世界状态、角色出场和截止，不自动播放连续剧情。
5. 方源是普通、可完全跳过的配角。
6. 玩家不接触方源也能完成全部必需主线。
7. 新手村限定奖励具有中期价值，并在离山后永久关闭。
8. 全部静态校验与代表性文档走查通过。
