# 低阶蛊虫获取、养护与配方接口设计

## 1. 状态与权限

本文定义青茅山精简 MVP 的低阶蛊虫范围、获取小游戏、炼化、自动养护、
空窍接口、配方接口、存档和高阶预留。

`docs/superpowers/specs/2026-07-27-qing-mao-simplified-mvp-design.md`
是低阶蛊玩法规则源；跨角色边界以
`2026-07-28-wave05-integration-contract.md` 为准。原著资料只用于确认蛊虫名称、品阶、能力、食性、来源和
具名后续形态，不覆盖总契约的低压力玩法边界。

本文不定义完整剧情、不创建高阶蛊掉落表，也不修改 `src/` 运行时代码。

## 2. 目标与边界

### 2.1 目标

1. 野生蛊通过观察、判断和准备取得，不靠重复刷怪。
2. 战斗是玩家修为进度的主要来源，持有更多蛊不增加每日操作量。
3. 每只低阶蛊只有一个清楚的主动定位和至多一个被动或探索功能。
4. 空窍容量迫使玩家取舍，但储备蛊和配方素材不丢失。
5. 喂养自动结算，断粮有宽限，恢复没有额外任务。
6. 配方使用数据接口扩展，不把未来材料压力提前塞进 MVP。
7. 三转是内容上限，四转及以上另立契约。

### 2.2 明确不做

本规范已删除或明确不做：

- 已删除逐只点击的每日喂养。
- 已删除每只蛊独立升级经验条和重复催动刷经验。
- 已删除证据式线索账本、追查、热度与复杂生态日程模拟。
- 已删除赃物、原主人和所有权追踪；偷盗取得后直接进入普通行囊。
- 已删除普通战斗随机掉蛊表。
- 不做四转及以上蛊虫的完整获取和养护。
- 不做高阶蛊战斗胜利后直接掉落。
- 不做未经原著资料确认的原创盗道蛊。

## 3. 玩家成长与蛊虫成长

### 3.1 玩家修为

蛊虫获取不建立第二条玩家等级线。玩家仍使用总契约的修为进度：

| 来源 | 基础修为 |
| --- | ---: |
| 普通战斗胜利 | `+8` |
| 精英或首领战斗胜利 | `+12` |
| 战斗失败或撤退但存活 | `+2` |
| 首次完成危险探索 | `+4` |
| 完成一次训练 | `+3` |
| 选择夜间修炼 | `+2` |

战斗贡献必须高于其他单一来源。夜间修炼完全可选，跳过不会失去蛊虫、
配方、剧情或突破资格。

### 3.2 蛊虫不设独立等级

MVP 的蛊虫实例没有经验条和可刷等级：

- 能力来自蛊定义、品阶和是否装入空窍。
- 熟悉蛊虫通过玩家构筑和实际使用表现，不另存每日经验。
- 具名后续形态通过配方产生，不由经验条自动变形。
- 原蛊被配方消耗时，已经写入玩家的永久炼体效果继续保留。

这使“养蛊”集中在获取、炼化、空窍取舍、自动补给和配方选择，而不是
重复劳动。

### 3.3 三转上限

- 一转、二转和三转蛊可以进入本次内容。
- 玩家达到对应境界后，才能炼化或装入同阶蛊。
- 三转是 MVP 上限。
- 四转及以上定义只能作为不可执行资料显示。

## 5. 获取框架

### 5.1 家族分配

月光蛊在开窍后的学堂选择中取得：

1. 进入学堂分配场景。
2. 查看当前可选蛊的名称与公开能力。
3. 选择月光蛊。
4. 创建一个稳定实例并加入蛊虫储备。
5. 保存，分配事件结束。

该流程没有随机判定，也不能通过重复对话复制同一实例。

### 5.2 野生生态捕捉

只有真正无主、低阶且已配置生态内容的蛊使用捕捉小游戏。酒虫是 MVP 唯一
完整样板。

酒虫保留以下原著事实：

- 青竹酒或对应高质量酒食可以诱出。
- 饮酒后会迟缓。
- 痕迹可以通向狭窄石缝和花酒传承入口。

小游戏新增的具体天气、容器和提示属于玩法创作，UI 必须与原著资料标签
区分。

### 5.3 传承取得

白豕蛊、玉皮蛊和地听肉耳草共用花酒传承地图：

1. 通过酒虫痕迹发现入口。
2. 完成第一段环境互动，开启第一地藏花并取得白豕蛊。
3. 使用白豕蛊完成明确的力量展示，打开第二段并取得玉皮蛊。
4. 到达后段，接受无血腥特写的移植场景并取得地听肉耳草。

每个地藏花只结算一次。保存、加载和重新进入地图不能复制奖励。三只蛊
共享地点和路线，不各自创建一套长期状态机。

### 5.4 家产、交易与偷盗

九叶生机草通过古月冻土相关家产场景进入玩家路线。内容可选择：

- 剧情直接结算。
- 普通交易。
- 使用地图偷盗。

偷盗完全遵守 `systems/theft-system-design.md`：靠近、查看、选择一件、
一次判定。成功后九叶生机草作为普通取得物进入玩家储备，保存后事件结束。

### 5.5 其他角色先取得

机缘可能先被其他角色取得。此时：

- 不复制第二个唯一实例。
- 原野节点标记该机会已经结算。
- 原著资料只提供已知去向，不强迫世界恢复。
- 后续是否能通过交易、偷盗或专门场景取得，由内容明确编写。
- 普通战斗胜利不自动转移蛊虫。

## 6. 捕捉小游戏

### 6.1 体验目标

捕捉不是“点击一次拿蛊”，也不是无限刷怪。一个完整机会由三段组成：

1. 在方向旅行中发现生态痕迹。
2. 根据有限线索配置诱饵、时机和容器。
3. 提交一次确定性收服判定。

完成全部准备可以把结果提升为必定成功。

### 6.2 有限线索

每个捕捉机会最多四条线索：

- 食性线索。
- 活动时机线索。
- 栖息地线索。
- 行为反应线索。

线索分布在首张野图的明确节点中。观察不消耗物品，不重复生成，并永久
保留到该机会结算。玩家不需要在同一天收齐，也不会因休息失去线索。

每条线索只给可判断的信息，例如“目标会被酒香吸引”，不直接替玩家选中
答案。

### 6.3 三槽准备

收服界面只提供三个槽位：

| 槽位 | 作用 | 酒虫样板正确项 |
| --- | --- | --- |
| 诱饵 | 让目标出现并停留 | 青竹酒 |
| 时机 | 决定目标活动状态 | 内容配置的活跃时段 |
| 容器 | 决定收束方式 | 软塞酒坛 |

每个槽位只显示三个以内的候选项。已经得到的线索会在相关候选旁显示来源
提示；未得到线索时仍可猜测。

### 6.4 成功率

三个槽位中正确项数量决定基础成功率：

| 正确槽位 | 成功率 |
| ---: | ---: |
| `0` | `40%` |
| `1` | `55%` |
| `2` | `70%` |
| `3` | `85%` |

当四条线索全部取得且三个槽位全部正确时，成功率提高到 `100%`。`100%`
结果不读取随机数。

该表属于捕捉小游戏，不与偷盗成功率共用，也不读取运气或盗道熟练。

### 6.5 提交与失败

一次提交：

- 消耗一个剧情时间增量。
- 只在内容明确要求时消耗一份诱饵。
- 成功时创建或转移该机会唯一的低阶蛊实例。
- 失败时不删除、不杀死、不复制目标。
- 失败会把一个尚未确认的槽位提示升级为明确线索。
- 重新进入对应野图后可再次准备。

失败不生成新任务，不重置已有线索，也不要求重新刷战斗。玩家收齐全部
信息后可以稳定结束机会。

### 6.6 原子顺序

成功结算：

1. 验证机会仍可用。
2. 验证三个槽位与成功率。
3. 必要时读取并推进捕捉随机游标。
4. 扣除本次时间与明确诱饵。
5. 创建或取得唯一蛊实例。
6. 标记机会完成。
7. 将入口、地点或后续传承发现写入当前世界。
8. 保存。

失败结算：

1. 验证机会仍可用。
2. 必要时读取并推进捕捉随机游标。
3. 扣除本次时间与明确诱饵。
4. 写入一条新的明确提示。
5. 保持机会可再次进入。
6. 保存。

任一步骤失败则整个事务回滚。

## 7. 炼化与存放

### 7.1 三种位置

- `aperture`：已经炼化并装入空窍。
- `reserve`：已经拥有但未装入。
- `material`：蛊材与配方材料。

取得蛊虫后默认进入 `reserve`。未炼化蛊可以查看、补给或作为配方明确允许
的输入，但不能催动主动技能和被动效果。

### 7.2 简化炼化

低阶蛊炼化为一次确定性确认：

1. 玩家境界不低于蛊虫品阶。
2. 玩家拥有蛊定义要求的真元。
3. 当前不在战斗中。
4. 确认后原子扣除真元。
5. 将实例标记为已炼化。
6. 默认放入 `reserve`；若空窍仍有容量，玩家可选择立即装入。
7. 保存。

炼化成功率为 `100%`，不读取随机数，不使用分段进度，也不要求额外安全
地点。

### 7.3 空窍负载

| 玩家境界 | 基础空窍容量 |
| --- | ---: |
| 一转 | `6` |
| 二转 | `10` |
| 三转 | `15` |

| 蛊虫品阶 | 负载 |
| --- | ---: |
| 一转 | `1` |
| 二转 | `2` |
| 三转 | `4` |

容量强化总计最多 `+3`。总负载超过容量时，整个换装操作失败且不部分写入。
战斗开始后不能在 `aperture` 与 `reserve` 之间换装。

## 8. 主动、被动与叠加

### 8.1 单蛊接口

每只蛊定义最多包含：

```js
{
  guDefinitionId,
  rank,
  load,
  signatureActive: null | {
    skillId,
    essenceCost,
    rangeTemplate,
    targetTemplate,
    effect
  },
  passiveOrExploration: null | {
    effectGroupId,
    effect
  },
  stackRule,
  recipeTags: []
}
```

低阶主动只使用 `melee`、`rangeN`、`lineN`、`radius1`、`self`。新射程模板
必须另开契约。

### 8.2 独立 `stackRule`

每只蛊必须选择：

- `unique`。
- `highestInstance`。
- `additiveCapped`，并提供硬上限。
- `recipeComponent`。

没有声明时默认为 `unique`。不同蛊修改同一效果组时，该效果组也必须声明
硬上限。不使用全局 `100% + 50% + 25%` 递减规则。

### 8.3 首批战斗接口

- 月光蛊：`line3` 单体月刃；同行或同列且无阻挡。
- 酒虫：无战斗按钮；修炼或真元规则读取其被动。
- 白豕蛊：无独立战斗按钮；已经获得的一豕之力进入普通肉搏计算。
- 玉皮蛊：`self` 防御 Buff，占用一个动作。
- 地听肉耳草：`self` 侦察，揭示已配置的有声单位或方向，不造成伤害。
- 九叶生机草：不直接产生战斗按钮；生机叶作为普通战斗道具使用。

具体伤害、真元消耗和 Buff 数值由格子战斗数据定义，但不得改变上述数量和
射程语义。

## 9. 杀招接口

低阶杀招固定使用：

```text
1 个核心蛊 + 0..2 个必需辅助蛊 + 0..1 个兼容可选修饰
```

每个杀招记录：

```js
{
  killerMoveId,
  coreGuDefinitionId,
  requiredSupportGuDefinitionIds: [],
  optionalModifierTag: null,
  essenceCost,
  rangeTemplate,
  targetTemplate,
  effect,
  consumesAction
}
```

核心或任一必需辅助未装入 `aperture` 时，不显示杀招按钮。可选修饰最多
改变一个声明参数，不生成第二个技能。MVP 只配置少量教学用杀招。

## 10. 低压力养护

### 10.1 原著食物与统一计量

| 蛊 | 原著食物摘要 | MVP 计量 |
| --- | --- | --- |
| 月光蛊 | 月兰花瓣 | `supplyDays` |
| 酒虫 | 青竹酒 | `supplyDays` |
| 白豕蛊 | 猪肉 | `supplyDays` |
| 玉皮蛊 | 玉石 | `supplyDays` |
| 地听肉耳草 | 人参根 | `supplyDays` |
| 九叶生机草 | 水与阳光 | `selfSustaining` |

UI 显示原著食物名称，日常只计算供应天数。资料尚未确认食性的升炼结果使用
`canonPending`，在资料补齐前不扣供应，也不猜测食物。

### 10.2 自动喂养

`autoFeed = true` 是新游戏和迁移默认值，MVP 不提供关闭按钮。

每日结束时：

1. `selfSustaining` 和 `canonPending` 视为已供应。
2. 其他已炼化蛊若 `supplyDays > 0`，自动扣除一天。
3. 供应归零后增加 `graceDays`.
4. 应用宽限状态。
5. 自动保存。

玩家不需要逐只点击，也不会因蛊虫数量增加每日操作。

### 10.3 一键补给

安全据点提供一个按钮：“补充全部已炼化蛊七日口粮”。

- 查看与补给不消耗剧情时间。
- 每只蛊最多储备 `21` 天。
- 只给 `supplyDays <= 14` 的蛊增加七天。
- 费用在确认前汇总显示。
- 元石不足时默认优先当前空窍中的蛊，玩家可以取消。
- 普通补给不生成任务、随机短缺或讨价还价界面。

### 10.4 宽限

| 连续零供应 | 状态 | 影响 |
| ---: | --- | --- |
| `0` | `fed` | 正常 |
| `1..6` | `grace` | 只提示，不降低任何能力 |
| `7+` | `dormant` | 不能催动；不会死亡或消失 |

补给后立即把 `graceDays` 归零并恢复 `fed`，不要求复苏物品、额外元石或
支线。休眠期间不产生永久损失。

界面只在进入宽限和进入休眠时各提示一次；重复读档不重复弹窗。

## 11. 配方接口

### 11.1 原则

- 结果必须是原著资料已确认的具名蛊。
- 玩家境界不得低于结果品阶。
- 输入与材料在确认前完整显示。
- 材料不足时按钮不可用，不做部分扣除。
- 满足条件后成功率为 `100%`，不读取随机数。
- 输入消耗、成本扣除、结果生成和保存原子完成。
- 结果最高三转。

### 11.2 数据形状

```js
{
  recipeId,
  resultGuDefinitionId,
  resultRank,
  recipeMode,
  inputGuRequirements: [],
  materialRequirements: [],
  environmentRequirements: [],
  cultivationRequirement,
  timeCost,
  essenceCost,
  stoneCost,
  canonicalSourceRefs: []
}
```

`recipeMode`：

- `mvpSimplified`：允许暂时省略尚未生产的材料。
- `canonicalRecipe`：完整读取已注册蛊材、环境和输入。

新增配方只增加数据，不修改核心结算顺序。

### 11.3 MVP 三条记录

| 结果 | 核心输入 | 时间 | 真元 | 元石 |
| --- | --- | ---: | ---: | ---: |
| 月芒蛊 | 月光蛊 | `2` | `8` | `8` |
| 四味酒虫 | 酒虫 | `2` | `8` | `8` |
| 白玉蛊 | 白豕蛊 + 玉皮蛊 | `2` | `10` | `12` |

三条记录均为 `mvpSimplified`。后续补齐原著配方时：

- 已经生成的结果不降级。
- 已完成记录不重新收费。
- 新执行只读取更新后的要求。
- 不追扣旧存档材料。

### 11.4 结算

1. 验证配方、玩家境界、输入、材料与成本。
2. 验证结果不超过三转。
3. 扣除真元、元石和材料。
4. 将输入蛊标记为已消耗。
5. 创建一个结果实例并放入 `reserve`。
6. 写入唯一 `recipeResolutionId`。
7. 保存。

同一 `recipeResolutionId` 再次提交时返回已有结果，不重复扣费或生成蛊虫。

## 12. 首批蛊的非战斗接口

### 12.1 月光蛊

- 可以切开内容明确标记为一转可破坏的藤蔓、绳索或薄障碍。
- 不自动发现隐藏路线。
- MVP 只开放月芒蛊分支。

### 12.2 酒虫

- 修炼时可让一转青铜真元临时提高一个小境界使用。
- 不提高资质。
- 不增加空窍容量。
- MVP 只开放四味酒虫结果。

### 12.3 白豕蛊

- 通过有限的力量展示节点形成一豕之力。
- 进度只由不同的明确节点推进，不通过每日重复训练刷取。
- 完成后写入永久角色效果；白豕蛊被配方消耗也不删除该效果。

### 12.4 玉皮蛊

- 催动后提供当前场景的防御效果。
- 可以通过明确标记的一转环境伤害检查。
- 不创建常驻防御成长条。

### 12.5 地听肉耳草

- 根须接地时揭示范围内已配置的有声事件类别和大致方向。
- 不显示隐藏路线答案、敌人完整属性或无声机关。
- 根须不能接地时按钮禁用并说明原因。

### 12.6 九叶生机草

- 自动维护叶片产出，不要求每日点击采摘。
- 有生机叶库存空间时，每个日结算最多自动生成一片。
- 生机叶作为普通治疗道具进入行囊。
- 交易产出必须有内容硬上限，避免无成本无限经济。

## 13. 高阶蛊预留

### 13.1 预留条件

未来的四转及以上蛊可以要求：

- 先通过战斗压制特定目标。
- 特定阵法或环境。
- 多步炼化程序。
- 完整复杂配方。
- 原著记载的专属条件。

本次只定义接口，不定义具体高阶蛊、掉落率、战斗关卡和材料数量。

### 13.2 战斗压制接口

高阶机会可读取：

```js
{
  opportunityId,
  suppressionEncounterId,
  suppressionSatisfied,
  requiredWorldConditionIds: [],
  requiredFormationIds: [],
  refinementProcedureId,
  canonicalConditionRefs: []
}
```

战斗胜利最多把特定机会的 `suppressionSatisfied` 写为 `true`。它不能创建
蛊虫实例、不能向行囊发放高阶蛊，也不能绕过其余条件。

### 13.3 边界

- 高阶蛊不进入普通掉落表。
- 本文不设计高阶蛊的战斗获取。
- 本文不设计高阶蛊的具体复杂条件。
- 四转及以上内容启用前必须新增独立规则与验证。

## 14. 确定性与存档

### 14.1 捕捉随机

捕捉使用当前远征的 `expeditionSeed` 与 `randomCursor`：

- 成功率低于 `100%` 的合法提交读取一次并推进游标。
- `100%` 提交不读取随机数。
- 无效提交不推进游标。
- 失败后新增提示与游标一起保存。
- 读档得到相同结果，不重掷。

### 14.2 最小蛊实例

```js
{
  instanceId,
  guDefinitionId,
  rank,
  location,
  refined,
  supplyDays,
  graceDays,
  careStatus,
  sourceOpportunityId,
  consumedByRecipeResolutionId
}
```

`location` 只允许 `aperture`、`reserve`、`material`。可自给或资料待确认的蛊
使用 `supplyDays = null`。

### 14.3 最小系统状态

```js
{
  autoFeed: true,
  guInstancesById: {},
  completedOpportunityIds: [],
  knownCaptureClueIds: [],
  completedRecipeResolutionIds: [],
  captureResolutionByOpportunityId: {}
}
```

所有列表按稳定 ID 去重。保存和加载不增加蛊虫数量、不重复日结算，也不
重置捕捉线索。

### 14.4 旧存档

迁移保留旧 payload，只为缺失的活动字段提供默认值：

- `autoFeed = true`。
- 已炼化蛊初始获得七天供应；可自给和资料待确认者除外。
- 不补算迁移前的断粮。
- 不复制已经存在的唯一蛊实例。
- 不追扣已经完成的简化配方成本。

## 15. UI

### 15.1 捕捉界面

只显示：

- 当前机会与目标能力大类。
- 已知线索。
- 诱饵、时机、容器三个槽位。
- 当前成功率。
- 提交后的即时结果。

未知答案不提前显示。四条线索和三项准备完整时明确显示 `100%`。

### 15.2 蛊册与空窍

每只蛊显示：

- 名称、品阶和原著能力摘要。
- `aperture` 或 `reserve`。
- 负载与总容量。
- 一个标志主动和至多一个被动/探索功能。
- `stackRule`。
- 食物名称、供应天数和宽限状态。
- 可用配方。

### 15.3 养护

养护界面只提供供应摘要与一键补给。没有逐只喂食按钮、每日任务和单蛊
经验条。

### 15.4 配方

配方界面显示输入、材料、结果、品阶、时间、真元、元石和
`mvpSimplified`/`canonicalRecipe` 标签。未开放的四转结果只可查看资料，
不可执行。

## 16. 验收标准

### 16.1 获取

- 月光蛊通过学堂分配，不进行随机捕捉。
- 酒虫通过有限线索、三槽准备和一次提交取得。
- 四条线索与三个正确槽位保证 `100%` 成功。
- 捕捉失败保留目标并明确一条新提示。
- 花酒传承的三个奖励各只能结算一次。
- 普通战斗不会随机掉落蛊虫。

### 16.2 构筑

- 一、二、三转容量分别为 `6`、`10`、`15`。
- 一、二、三转蛊负载分别为 `1`、`2`、`4`。
- 超载换装整笔失败。
- 战斗中不能换装空窍。
- 每只蛊最多一个标志主动和一个被动或探索功能。
- 每只蛊独立声明 `stackRule`。
- 杀招只采用核心、必需辅助和一个可选修饰。

### 16.3 低压力养护

- 持有六只蛊也不增加每日点击。
- 自动喂养固定开启。
- 供应归零后有六天无惩罚宽限。
- 休眠蛊补给后立即恢复且没有永久损失。
- 蛊虫没有独立经验条和重复刷取要求。

### 16.4 配方与上限

- 三条 MVP 配方满足条件后确定成功。
- 输入、成本、结果和保存原子结算。
- 完成记录读档后不重复收费或生成结果。
- 新配方可以只通过数据添加。
- 三转是可执行上限。

### 16.5 高阶边界

- 高阶蛊只保留复杂条件与战斗压制接口。
- 战斗压制只写入条件完成，不发放蛊虫。
- 没有高阶蛊掉落表、掉落率或具体获取关卡。
- 四转及以上在新增独立契约前不可执行。
