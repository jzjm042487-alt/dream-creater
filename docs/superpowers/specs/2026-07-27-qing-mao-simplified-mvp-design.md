# 《蛊真人：天外盗剧本》青茅山精简 MVP 规则总契约

## 1. 文档地位

本文是青茅山精简 MVP 的系统范围与玩法规则源。跨角色冲突、叙事接入和
Wave 1 入口以 `2026-07-28-wave05-integration-contract.md` 为最高层契约。

其他文档的职责如下：

- GDD 解释整体体验与内容范围。
- `systems/` 给出可实现公式与状态转换。
- 完整剧本只写场景、对白、战斗、旅行和即时奖励。
- UI 规格只写界面、交互和表现。
- JSON Schema 约束可生产的数据形状。

系统公式或删除项发生冲突时以本文为准；剧情事实与条件以状态化剧本为准。
两者发生跨层冲突时按 Wave 0.5 集成契约裁决。原有复杂状态模拟、方源专属系统、
证据系统、回溯修正和旧 UI 面板均不再具有实施效力。

本轮只修改设计、内容契约、Schema 和验证，不修改 `src/` 运行时代码。

## 2. 产品目标

### 2.1 一句话体验

玩家在依据原著初始化的青茅山自由行动，通过方向旅行发现地点和机缘，收集、培养并搭配低阶蛊虫，在 `8 x 6` 格子战斗中争夺资源，同时用独立于蛊虫的偷盗技能取得物品。

### 2.2 核心循环

1. 查看当前主线步骤、附近角色和可查询的原著资料。
2. 在地图中移动、对话、训练、偷盗或进入野外。
3. 在野外使用前、后、左、右旅行，触发探索、小游戏、奇遇或战斗。
4. 获得蛊虫、蛊材、装备、元石和修为进度。
5. 调整空窍中的蛊虫负载、被动效果和战斗技能。
6. 完成当前剧情步骤，进入下一步骤。

主线不会因为玩家探索、休息或错过可选机缘而过期。

## 3. 明确删除的系统

| 删除项 | MVP 处理 |
| --- | --- |
| 好感、信任、怀疑、警觉、杠杆、功绩数值 | 不创建、不显示、不作为任务条件 |
| 证据、可信度、时间线、矛盾与破案任务 | 整体取消 |
| 疲惫、身份暴露、旧债、血污 | 不属于活动玩家状态 |
| 赃物、原主人、非法占有与所有权追踪 | 偷盗成功后物品直接进入普通行囊 |
| 失主线索、追查、热度、嫁祸与洗白 | 整体取消 |
| 方源警觉、认知权重、专属观察和剧情保护 | 整体取消 |
| 原轨同步率、偏移值、纠偏惩罚 | 整体取消 |
| 行动点、对话风险公式、独立锁定系统、二次确认 | 整体取消；内容条件不满足时可禁用选项并显示原因 |
| 独立判定页 `UI12` | 结果在原交互内显示 |
| 证据页 `UI14` | 删除 |
| 回溯修正页 `UI16` | 删除 |
| 任务百分比、通用补救系统与复杂状态矩阵 | 删除；主线内容仍必须提供合法继续记录 |
| 战斗中断条件与反应窗口 | 删除 |

这些名词只允许出现在“已删除”“不做”或旧存档兼容说明中。

## 4. 世界与原著

### 4.1 原著的职责

原著资料只做两件事：

1. 初始化人物、势力、地点、血脉关系、亲朋关系、主修方向、公开能力与机缘记录。
2. 供玩家查询原著中的人物、时间、地点、物品和机缘。

游戏开始后，人物死亡、机缘归属、势力变化和剧情结果只由游戏规则与已经发生的行动决定。系统不尝试把世界拉回原著。

### 4.2 查询外挂

查询界面提供五类过滤：

- 人物。
- 时间段。
- 地点。
- 蛊虫或物品。
- 机缘。

每条结果只包含资料摘要、原著位置、已知时间窗和关联对象，不复制长段原文。

查询：

- 不消耗行动点、精神、元石或其他资源。
- 不增加任何关注、同步或偏移数值。
- 不自动生成强制任务。
- 不保证机缘仍按原著存在；结果必须标记“原著资料”或“当前世界已确认”。

### 4.3 方源与天骄

方源与方正、漠北、赤城、白凝冰等人共同进入“天骄名册”。

名册只展示玩家已知的：

- 境界。
- 公开蛊虫。
- 最近公开战绩。
- 当前状态：活跃、受伤、失踪、离山或死亡。

方源使用普通角色、普通战斗和普通死亡规则。合理的致命战斗可以让其提前死亡；后续场景使用通用缺席替代，不复活、不纠偏。

## 5. 活动玩家状态

### 5.1 唯一活动字段

活动玩家状态只包含：

- 生命。
- 真元。
- 元石。
- 境界。
- 修为进度。
- 属性。
- Buff。
- Debuff。

MVP 属性为：

- 力量：物理攻击与负重相关。
- 身法：移动和部分技能相关。
- 感知：探索与目标观察相关。
- 运气：偷盗与机缘结果相关。
- 意志：控制、毒与精神类抗性相关。
- 盗道熟练：偷盗成功率和技能树条件。

所有属性采用 `0..100` 整数。活动状态结构由 `contracts/player-state.schema.json` 约束。

### 5.2 Buff 与 Debuff

状态只允许三种持续期：

- `turns`：战斗回合结束时减少。
- `scene`：离开当前地图、对话或战斗时清除。
- `untilRest`：完成一次休息时清除。

每个状态实例保存 `id` 与 `duration`。`turns` 状态还必须保存正整数
`remainingTurns`；另两种持续期禁止保存该字段。Buff ID 与 Debuff ID 使用
不同注册桶，同一数组内不得重复同一 ID。

MVP 不创建跨章节的隐藏负面状态。状态必须显示名称、效果和剩余持续期。

## 6. 修为与突破

### 6.1 修为来源

修为进度范围为 `0..100`。

| 来源 | 基础修为 |
| --- | ---: |
| 普通战斗胜利 | `+8` |
| 精英或首领战斗胜利 | `+12` |
| 战斗失败或撤退但存活 | `+2` |
| 首次完成危险探索 | `+4` |
| 完成一次训练 | `+3` |
| 选择夜间修炼 | `+2` |

约束：

- 同一个战斗实例只结算一次。
- 同一个危险探索节点只结算一次首次奖励。
- 训练每个剧情步骤最多结算一次。
- 夜间修炼完全可选，跳过不会丢失剧情或突破资格。
- 平均进度中，战斗贡献必须高于其他单一来源。

### 6.2 溢出

结算修为时：

```text
raw = cultivationProgress + gain
cultivationProgress = min(100, raw)
storedOverflow = max(0, raw - 100)
```

`storedOverflow` 最大为 `20`，只等待本次突破，不是新货币。

### 6.3 突破

当当前境界的 `cultivationProgress === 100` 时，突破按钮立即可用。

突破不检查：

- 所在地点。
- 是否安全。
- 元石储备。
- 特定时间。
- 好感、功绩或任务状态。
- 随机成功率。

结算顺序：

1. 确认当前境界不是 MVP 上限。
2. 境界提升一级。
3. `cultivationProgress = storedOverflow`。
4. `storedOverflow = 0`。
5. 生命与真元恢复到最大值。
6. 写入一次突破记录并保存。

突破确定成功。三转为本次内容上限；达到上限后进度可停在 `100`，但不能进入四转。

## 7. 空窍、蛊虫与构筑

### 7.1 三种存放位置

- `aperture`：已炼化并装入空窍，战斗技能和被动效果可用。
- `reserve`：已拥有但未装入，只能查看、喂养、炼制或换装。
- `material`：蛊材和配方材料，不是可用蛊虫。

战斗开始后不能在 `aperture` 与 `reserve` 之间换装。

### 7.2 容量

| 境界 | 基础空窍容量 |
| --- | ---: |
| 一转 | `6` |
| 二转 | `10` |
| 三转 | `15` |

蛊虫负载：

| 蛊虫阶位 | 负载 |
| --- | ---: |
| 一转 | `1` |
| 二转 | `2` |
| 三转 | `4` |

容量强化最多提供 `+3`。若装入后总负载超过容量，换装操作失败，不产生部分写入。

同种素材蛊、合炼素材和重复蛊可以放在 `reserve`，因此二转、三转配方不会被“战斗只能带一只”阻断。

### 7.3 单只蛊的技能数量

一只蛊在 MVP 中最多包含：

- 一个标志性主动技能。
- 一个被动效果或探索功能。
- 若干配方标签。

纯被动蛊可以没有主动技能。复杂的多段战斗能力由杀招组合产生，不给每只低阶蛊堆叠多个按钮。

### 7.4 重复与叠加

不存在全局通用的 `100% + 50% + 25%` 规则。每只蛊必须声明以下一种 `stackRule`：

- `unique`：同 ID 只生效一只。
- `highestInstance`：同 ID 只取数值最高的一只。
- `additiveCapped`：可相加，但必须声明硬上限。
- `recipeComponent`：不提供重复数值，只作为炼制或杀招组件。

不同蛊若修改同一效果组，也必须由该效果组声明上限。没有明确契约时默认 `unique`。

### 7.5 杀招

MVP 杀招使用固定核心结构：

```text
1 个核心蛊 + 0..2 个必需辅助蛊 + 0..1 个兼容可选修饰
```

杀招必须声明：

- 核心蛊 ID。
- 必需辅助蛊 ID。
- 可选修饰标签。
- 真元消耗。
- 射程模板。
- 目标模板。
- 伤害或状态效果。
- 是否占用本回合动作。

缺少核心或任一必需辅助时，杀招按钮不可出现。可选修饰只改变一个已声明参数，不创造第二套技能。

### 7.6 高阶预留

本次只制作三转以下低阶蛊。

高阶蛊未来可要求：

- 先通过战斗压制。
- 阵法或环境条件。
- 特定炼化步骤。
- 复杂配方。
- 原著中的专属条件。

战斗胜利不能直接把高阶蛊作为普通掉落放入行囊。该接口只预留，不在 MVP 实现。

## 8. `8 x 6` 格子战斗

### 8.1 战场

- 宽 `8` 格，高 `6` 格。
- 左上角为 `(0, 0)`，右下角为 `(7, 5)`。
- 默认 `1v1`，少量事件允许 `1v2`。
- 单位不能重叠。
- 移动只使用上下左右，不走对角线。
- 距离统一使用曼哈顿距离。

### 8.2 回合

每个玩家回合：

1. 可移动一次，最多移动角色的 `move` 格，也可以不移动。
2. 执行一个动作：普通攻击、蛊虫主动技能、杀招、防御、使用道具或撤退。
3. 结算回合末 Buff/Debuff。
4. 敌方单位按固定顺序行动。

移动与动作不使用行动点池。没有待机反击、反应动作或中断条件。

### 8.3 射程模板

| 模板 | 规则 |
| --- | --- |
| `melee` | 曼哈顿距离 `1` |
| `rangeN` | 曼哈顿距离 `1..N` |
| `lineN` | 同一行或同一列，距离 `1..N`，被单位或障碍阻挡 |
| `radius1` | 目标格及其上下左右四格 |
| `self` | 仅自己 |

低阶主动蛊只使用上述模板。新模板必须另开契约，不由内容作者临时发明。

### 8.4 普通肉搏

玩家始终拥有普通肉搏，不需要蛊虫：

- 射程：`melee`。
- 基础伤害：`6 + floor(strength / 20)`。
- 真元消耗：`0`。

肉搏可以作为主构筑，但跨境界作战的额外能力必须来自炼体蛊、装备或 Buff。

### 8.5 伤害

MVP 不使用命中随机数。处于合法射程即可命中。

```text
physicalDamage = max(1, basePower + floor(strength / 20) - targetPhysicalDefense)
guDamage = max(1, basePower + floor(perception / 25) - targetGuDefense)
```

技能若声明固定伤害，则不再加属性。所有取整向下。

### 8.6 防御与撤退

- 防御：本回合结束，下一次受到的伤害减半，向下取整，最低仍为 `1`。
- 撤退：玩家位于任一边缘格时可用，占用动作并立即结束战斗。

### 8.7 敌方 AI

敌方 AI 使用“行为模板、合法动作枚举、效用评分和浅层确定性搜索”，完整
规则以
`docs/superpowers/specs/2026-07-27-tactical-combat-ai-and-enemy-balance-design.md`
为准。

游戏提供入门、标准、困难、天骄四档，默认标准。难度只改变候选选择和搜索
深度，不改变敌人生命、伤害、真元、移动力、技能、奖励或失败结果。

敌人只能读取公开棋盘、可见状态和玩家在本场战斗中已经公开的动作。等长
路径按上、左、右、下决定；同一战斗状态、难度、种子和随机游标必须得到
同一动作，读档不得重掷。

### 8.8 结束

每次动作或回合末结算后按固定顺序只产生一个结果：

1. 所有敌人生命归零：胜利。
2. 否则玩家生命归零：失败。
3. 否则撤退动作成功：撤退。
4. 否则继续战斗。

玩家与最后一名敌人同时归零时按胜利处理，不存在平局。

失败后玩家回到战斗入口节点，生命恢复到最大值的 `30%`，保留物品、蛊虫、元石和修为，并获得一个持续到休息的 `debuff_wounded`。不产生债务、掉落物、追查或剧情惩罚。

## 9. 偷盗

### 9.1 与蛊虫分离

偷盗只依赖玩家属性和偷盗技能树，不要求装备盗道蛊。

蛊虫未来可以提供已声明的 Buff，但不能替代盗道熟练，也不能开启隐藏的第二套偷盗规则。

### 9.2 地图操作

完整流程只有五步：

1. 玩家在地图上靠近角色。
2. 选择“偷盗”。
3. 查看该角色当前可偷物品。
4. 选择一件物品。
5. 进行一次成功或失败判定，并在地图交互层显示结果。

每名目标每次地图访问只能尝试一次。离开并重新进入地图后可再次尝试。该限制属于当前地图会话，不是追查状态。

### 9.3 可偷物品

目标清单可以包含：

- 普通道具。
- 元石袋。
- 蛊材。
- 装备。
- 外衣。
- 成年角色的贴身物品。

未成年角色不得配置贴身物品偷盗条目。表现遵守角色立绘规范，不展示裸体或具体隐私物品。

### 9.4 成功率

境界序号：凡人 `0`、一转 `1`、二转 `2`、三转 `3`。

```text
rankGap = targetRankIndex - playerRankIndex
luckBonus = round((luck - 50) * 0.20)
masteryBonus = round((theftMastery - 50) * 0.35)
rankModifier =
  rankGap > 0 ? -10 * rankGap
              : 5 * min(-rankGap, 2)

itemPenalty:
  ordinary = 0
  equipment = 5
  outerwear = 8
  closeWorn = 10
  secured = 15

rawChance = 65 + luckBonus + masteryBonus + rankModifier - itemPenalty
finalChance = clamp(15, 95, rawChance)
```

所有运算使用整数。`round` 为四舍五入。

因此：

- 同境界、运气 `50`、盗道熟练 `50`、普通物品为 `65%`。
- 任意合法目标最低仍有 `15%`。
- 偷盗主修角色在同境界下通常保持高于一半的成功率。

### 9.5 随机与读档

判定使用存档中的 `theftSeed` 与 `theftRandomCursor`。选择物品后先取得下一随机值，再立即递增并保存游标。

读取判定前的存档会得到同一结果；读档不能重掷。

### 9.6 成功结算

成功按以下原子顺序：

1. 消耗本次地图访问对该目标的尝试资格。
2. 从目标当前可偷清单移除所选条目。
3. 将物品作为普通物品加入玩家行囊。
4. 若是服装或贴身物品，写入直接展示标签。
5. 若条目声明即时 Buff/Debuff，应用该效果。
6. 显示成功结果。
7. 保存。

第 7 步完成后事件结束。禁止写入原主人、赃物、非法占有、失主线索、追查、热度或后续归因。

### 9.7 失败结算

失败按以下顺序：

1. 消耗本次地图访问对该目标的尝试资格。
2. 不转移物品。
3. 播放目标的即时反应气泡或当前场景立绘。
4. 显示失败结果。
5. 保存。

失败不创建跨场景状态。只有当前场景明确写了“失败立即开战”时才进入普通战斗；这不是追查系统。

### 9.8 服装与情绪表现

服装偷盗使用直接标签，不使用情绪数值：

- `portrait_normal`。
- `portrait_outerwear_missing`。
- `portrait_close_worn_missing`。

可同时添加一个作者指定的情绪标签，例如 `embarrassed`、`angry` 或 `guarded`。关键衣物可直接赋予当前场景或下一场战斗的 `debuff_suppressed`，但不创建心情条。

地图 Q 版角色不随这些标签换图。

### 9.9 技能树边界

盗道技能树保留从约序列八水平到半神前的成长感，但 MVP 只实现前三层：

1. `摸索者`：查看可偷清单、普通物品成功率加成。
2. `巧手`：可偷装备与外衣、降低物品惩罚。
3. `无形手`：可偷成年角色贴身物品、失败时可避免当前场景开战一次。

后续层只在文档预留，不实现偷取记忆、身份、命运、概念或规则。

升级资源为盗道技能点。技能点来自：

- 首次成功偷取某类物品。
- 完成明确的偷盗挑战。
- 剧情里程碑。

重复刷同一角色、同一物品类别不提供技能点。

## 10. 地图与野外旅行

地图移动不通过点击地点传送。

进入野外后只使用：

- 前。
- 后。
- 左。
- 右。

绝对方位、初始朝向、相对方向换算、可逆历史栈、连续后退、时间收费、目的地状态、第 20 步保底、战斗返回、事件生命周期、确定性随机与 v2 到 v3 迁移，全部以 `2026-07-26-wilderness-hidden-route-design.md` 为准。

这些状态只属于当前远征，不影响好感、任务资格或世界压力。

野外节点可以触发：

- 低阶蛊虫追踪小游戏。
- 捕捉小游戏。
- 危险探索。
- 普通战斗。
- 一次性机缘。
- 环境提示。

高阶蛊不得作为普通野外掉落。

## 11. 任务与剧情流程

### 11.1 任务实例

任务只保存：

- `status`：`inactive`、`active` 或 `completed`。
- `currentStepId`。
- `nextStepId`，若已完成则省略；禁止写入 `null`。

UI 只显示：

- 当前步骤。
- 下一步骤。
- 是否完成。

不显示百分比、门槛列表或补救路线。

### 11.2 推进

每个主线步骤有一个明确的 `completionTrigger`。触发后按以下顺序：

1. 结算当前场景即时奖励。
2. 标记当前步骤完成。
3. 将 `currentStepId` 切换到 `nextStepId`。
4. 更新新的下一步骤。
5. 保存。

主线不得把好感、功绩、证据数量、属性阈值或物品储备设为唯一推进门槛。
可选分支可以读取明确物品、知识、世界事实或能力条件，但条件不满足时主线仍须保留合法出口。

“第 0 日”到“第 30 日”只是章节序号，不是倒计时。休息和自由探索不会导致主线失败。

### 11.3 可选机缘

五条机缘统一使用：

- `inactive`：尚未开放。
- `available`：可在地图进入。
- `contested`：至少两名角色正在争夺。
- `resolved`：结果已经固定。
- `gone`：机缘消失且无人取得。

机缘状态与任务状态是两套独立枚举，不使用 `open` 或 `unknown`。
只有 `resolved` 可以保存 `resolvedByCharacterId`；`gone` 明确表示无人取得。

可选机缘：

- 可以错过。
- 不阻断主线。
- 不生成补救任务。
- 只改变玩家所得、角色存亡或当前世界事实。

### 11.4 离山

到达最后主线步骤后直接显示离山路线选择。商队关系、功绩、属性和证据不参与解锁。

## 12. 人物关系

人物关系是无数值图谱。

每条边只包含：

- 起点角色。
- 终点角色。
- 关系类别。
- 可选说明。

关系类别包括血亲、配偶、远亲、朋友、师徒、竞争者和熟人。父子等有方向的关系使用成对角色边；兄弟、朋友等对称关系由内容同时写入双向边。

关系图用于：

- 展示原著初始化的人物谱。
- 帮助玩家理解人物。
- 记录明确发生的身份变化，例如结为师徒。

关系图不用于：

- 检定加成。
- 任务门槛。
- 解锁离山路线。
- 计算 NPC 是否相信玩家。

## 13. 对话

对话界面只包含：

- 场景背景。
- 当前角色立绘。
- 角色名与台词框。
- 最多三个简短选项。

选项可以：

- 进入下一对白节点。
- 结束对话。
- 触发一个即时事件增量。
- 进入地图、战斗或商店。

内容字段为 `action`，只取 `nextNode`、`endDialogue`、`openMap`、
`startBattle`、`openShop`、`openPanel`、`openOpportunity` 或
`applyEventDelta`。除 `endDialogue` 外，每种动作只携带自己的一个目标
字段；不得用空的 `nextNodeId` 冒充结束动作。

选项不得显示 AP、成功率、风险公式、锁形图标或二次确认。

## 14. 行囊、装备与炼制

行囊保留：

- 普通道具。
- 蛊材。
- 蛊虫储备。
- 武器。
- 防具。
- 法器。
- 配方。

所有取得的物品只有一个普通持有状态。若保留通用获得日志，只记录物品 ID、
数量和获得时间；不得记录来源角色、原主人、地点或合法性，且该日志不得参与
使用、出售、炼制或任务判断。

炼制 MVP：

- 支持已有低阶配方。
- 配方声明输入、数量和输出。
- 材料不足时按钮不可用。
- 不增加额外炼制压力条。
- 后续可通过数据新增配方和资源，不修改核心流程。

## 15. UI 面板

活动 MVP 面板为：

1. 地图与常驻 HUD。
2. 对话。
3. 角色、属性与空窍。
4. 行囊、装备与炼制。
5. 当前任务。
6. 天骄名册。
7. 原著资料查询。
8. `8 x 6` 战斗。
9. 暂停、存档与读档。
10. 地图交互结果覆盖层。

常驻 HUD 只显示生命、真元、元石、境界、Buff/Debuff 摘要和当前任务步骤。

## 16. 存档与兼容

### 16.1 Key

读取顺序：

1. `tianwai-daojuren-save-v3`。
2. `tianwai-daojuren-save-v2`。

迁移后写入 v3 key，不删除 v2 key。

### 16.2 作者契约与旧存档分离

新内容必须通过精简 Schema，旧字段在新作者数据中会以字段级错误失败。

旧存档迁移则遵循无损原则：

- 按现有 `{ state, journal }` 包装完整复制 v2 payload。
- 只添加活动精简分支和缺失的 v3 默认值。
- 原有 `fangYuan`、`clues`、数值关系、行动点或其他旧分支可以原样保留。
- 活动 MVP 系统禁止读取、显示、更新或分支判断这些旧字段。

因此“保留旧数据”不等于“继续运行旧系统”。

活动 `state.mvp` 必须保存玩家、主线步骤、行囊数量、装备槽、已解锁配方、
已发现地点、五条机缘状态、人物存亡与位置、偷盗游标、战斗和唯一奖励记录。
精确包装、字段路径、`world` 场景默认值和旧 v3 补全规则以
`contracts/game-state-v3.md` 为准。

### 16.3 不重掷

存档必须保留：

- 野外 `expeditionSeed` 与 `randomCursor`。
- 偷盗 `theftSeed` 与 `theftRandomCursor`。
- 当前战斗状态与固定 AI 顺序。
- 行囊、装备、配方、地点、机缘与人物存亡。
- 已结算战斗、探索、炼制和突破的唯一记录。

读档不重复奖励、不重复结算、不改变下一随机结果。

## 18. 验收

### 18.1 规则验收

- 玩家可以不进行夜间修炼而完成主线。
- 修为满后可以立即突破，无其他门槛和失败率。
- 偷盗成功后物品立即成为普通行囊物品，事件结束。
- 任意合法偷盗目标成功率不低于 `15%`。
- 任务只显示当前、下一和完成状态。
- 方源可以通过普通战斗死亡，流程仍能继续。
- 战斗只使用移动和一个动作，不存在中断条件。
- 原著查询不改变世界数值。
- 离山选择在最终步骤直接出现。

### 18.2 契约验收

- 所有有效 JSON 示例通过 `validate-contracts.mjs` 和 `validate-content.mjs`。
- 未知 ID 在具体字段路径失败。
- 被删除字段因 `additionalProperties: false` 在具体字段路径失败。
- 临时无效样例在系统临时目录创建，并在 `finally` 中清理。
- 存档迁移保留旧 payload，但活动文档不把旧字段当作规则输入。
