# 《蛊真人：天外盗剧本》青茅山 MVP 生产剧本

版本：`1.0-rc1`

状态：30 日主线、5 条支线和重复交互已写完，并通过实现前独立规格复审。

本目录是可直接拆成剧情事件数据的生产剧本，不是剧情提纲。

系统数值、判定公式、行动成本、状态字典、奖励和结局条件以
[`2026-07-26-qing-mao-mvp-complete-script-design.md`](../../superpowers/specs/2026-07-26-qing-mao-mvp-complete-script-design.md)
为准；本目录负责逐场演出、逐句对白、选项回应和剧情跳转。

规格正文中的 `[SYS] / [NPC:name] / [CHOICE]` 是机制说明层标记；本目录使用
`[系统] / [角色名] / [选项]` 作为生产台词层标记。两者语义相同，导入时以本目录文本为准。

## 2. 每场必须具备

```text
场景 ID
时间与地点
触发条件
入场状态
演出与逐句对白
玩家全部选项
每个选项的角色回应
判定四档结果对白；二元门槛、双方对抗或共享结算块可使用明示的专用结果标签
状态写入
下一场跳转
缺席角色替代
```

生产数据不得只写“进入某路线”“关系上升”而没有角色回应和下一场。

## 3. 标记

- `[镜头]`：背景、立绘、地图位置和镜头运动。
- `[音效]`：一次性环境或战斗音效。
- `[动作]`：角色可见动作。
- `[停顿]`：有意保留的节奏。
- `[玩家]`：玩家角色在世界内说出的话。
- `[玩家选择]`：创建角色等纯系统界面中确认的 UI 输入，不是世界内台词。
- `[系统]`：只有现实玩家能看见的生成器信息。
- `[旁白]`：不可交互叙述。
- `[选项]`：UI 选项标题。
- `[前置] / [触发] / [地点] / [目标]`：事件数据的条件和演出元数据，不显示为角色台词。
- `[判定]`：读取系统规格中的判定。
- `[写入]`：原子状态变化。
- `[跳转]`：下一场景 ID。
- `[关闭]`：永久错过或当前存档互斥。

其他方括号标签均为说话人，例如 `[方源]`、`[铁若男]`。`[持有人]`、`[对手]`、`[方源或代理人]` 等动态标签必须先由场景演员解析器替换成实际角色；`[白凝冰日志]` 一类标签是系统展示的已记录文本，不生成在场角色。

玩家 UI 可以显示“截胡酒虫”“利用原作情报”等元信息；`[玩家]` 台词必须始终是世界内角色能理解的说法。

## 6. 场景跳转原则

1. 每日先播强制主线，再开放三个自由行动。
2. 自由行动命中支线条件时跳入对应支线文件，结束后返回当日地图。
3. 日终先结算限时支线，再播日终人物场。
4. 主线不会等待支线；错过后按失败对白继续。
5. 方源不因高警觉凭空出现。只有当前目标重叠时，支线场景才能把他加入演员列表。
6. 第 29 日第二轮不是重玩九个普通行动，只播放三场“修正行动”及被改变后的关键场。
7. `06-repeatable-dialogue.md` 的场景完成后总是返回调用它的地图交谈界面，不推进时间，也不需要逐场重复写 `[跳转]`。

支线场景以调用栈方式进入：支线文件写明具体目标时按 `[跳转]` 进入该目标；支线场景只写“返回当日地图”时，返回调用它的主线自由行动槽。`[关闭]` 是该路线的永久终点，不再要求返回。只有可变演员可能缺席的场景才需要单独写替代角色；其余场景使用规格 15.4 的全局替代规则。

## 7. 角色台词约束

- 方源不解释价值观，不说空泛狠话；他通过算成本、问来源、指出破绽表达判断。
- 方正说话常先寻求认可，再为家族或哥哥辩护；关系变化后才逐渐使用自己的判断。
- 青书不接受“你会死”作为充分理由；他的对白始终追问任务由谁承担、其他人怎么撤。
- 贾金生用夸张自信遮掩对贾富的恐惧；贪欲高时会主动把关系变成价码。
- 贾富不靠威胁维持气场；他用账、损失和可验证性压迫对方。
- 白凝冰的兴趣不是好感；越感兴趣，台词越直接逼迫玩家承担危险。
- 铁若男不猜心，只拆时间线、来源和矛盾。
- 生成器只报告已知、推演和偏移，不替玩家评价道德。

## 8. 状态编译规则

生产剧本允许用便于编剧阅读的短写，但导入任务数据前必须展开为规格 15.2 的规范键：

| 剧本短写 | 规范键 |
| --- | --- |
| `方源警觉`、`fang_yuan.alert` | `npc.fang_yuan.alert` |
| `方正自我价值` | `npc.fang_zheng.self_worth` |
| `青书信任` | `npc.qing_shu.trust` |
| `赤城竞争` | `npc.chi_cheng.relationship_facets.competition` |
| `赤城秘密压力` | `npc.chi_cheng.relationship_facets.secret_pressure` |
| `漠北尊重` | `npc.mo_bei.relationship_facets.respect` |
| `Q01_state` 至 `Q05_state` | `quest.q01.state` 至 `quest.q05.state` |
| `source_sync` | `generator.source_sync` |
| 无命名空间的已验证情报 | `player.knowledge_flags.<flag_id>` |
| 无命名空间的世界事件 | `world.flags.<flag_id>` |
| 唯一物品持有人 | `item.unique.<ITEM_ID>.owner` |

上下文展开规则：

- `Qxx=<state>` 或 `Qxx 状态 <state>` 展开为 `quest.qxx.state=<state>`。
- 在 `Qxx-*` 场景中，裸任务字段展开到 `quest.qxx.*`；例如 Q02 的 `boar_strength` 是 `quest.q02.boar_strength`。
- `claim_flags`、`clue_flags`、`evidence_flags`、`preparation_flags` 中的成员写成集合增删，不创建同名布尔顶层键。
- 角色名加“信任、怀疑、警觉、尊重、竞争、压力”等关系词，展开到对应 NPC 通用字段或已声明的 `relationship_facets`。
- `ITEM_*` 表示物品定义 ID；“获得/消耗”分别编译为 `player.inventory` 原子增删，唯一蛊额外更新其所有权键。
- 纯枚举值、场景 ID、物品 ID 和台词中展示的关键词不作为状态键处理。

方括号内的人类可读结果不是第二套状态。导入器必须拒绝未出现在规格状态字典或本表中的裸键。

## 9. 模板变量

| 变量 | 运行时来源 |
| --- | --- |
| `{player_name}` | 创建角色时确认的古月姓名 |
| `{reroll_index}` | 当前第几次 Roll |
| `{aptitude}` | Roll 得到的资质 |
| `{aperture_capacity}` | Roll 得到的空窍容量 |
| `{cultivation_multiplier}` | 资质对应修炼倍率 |
| `{primary_gu}`、`{secondary_gu}` | 当前配蛊选择 |
| `{proxy_id}`、`{proxy_name}` | Q04 已选且信任达标的代理人 |
| `{selected_suspect}` | Q03 玩家指认对象 |
| `{npc_id}` | 当前场景已经确认的 NPC，例如代持者或第 29 日修正目标 |
| `{item_id}`、`{evidence_id}`、`{route_id}`、`{decoy_id}` | 第 29 日修正目标选择 |

所有变量在显示前必须完成解析；解析失败时选项保持禁用并显示缺失条件，不允许把花括号原样展示给玩家。
